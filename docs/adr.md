# ADR: API Tracker CLI 기술 결정 기록

## ADR-001: Replay 기반 상태 복원 (DB 스냅샷 대신)

**결정**: 지정 Node까지 Edge(API 호출)를 순서대로 재실행하여 상태를 복원한다.

**대안 기각**: DB 스냅샷(pg_dump, docker commit 등)은 노드마다 저장 시 디스크 부담이 크고 속도가 느리다.

**트레이드오프**: 비결정적 응답(UUID 등)으로 인해 동일 상태 보장이 안 됨 → 바인딩 엔진으로 해결. 체인이 길어지면 replay 시간 증가 → 현실적 시나리오(수십 호출)에서 허용 범위로 판단.

---

## ADR-002: 하이브리드 바인딩 (명시적 템플릿 + UUID 자동 추론)

**결정**: `$ref(node.N.response.path)` 템플릿을 우선 사용. 미사용 시 UUID 등 고유성 높은 값만 자동 매칭.

**배경**: 서버에 테스트용 고정 UUID/시간 주입 API를 만들지 않기로 결정. 비결정성은 클라이언트 측에서 해결해야 함.

**자동 추론 범위 제한 이유**: `"page": 1` 같은 흔한 값까지 매칭하면 오탐 발생. UUID 포맷 등 고유성이 높은 패턴만 대상으로 한정.

**추론 실패 시**: 경고 출력 후 진행. 차단하면 AI agent 흐름이 끊기므로 감지 목적에 맞게 비차단.

---

## ADR-003: Node=상태, Edge=API 호출 그래프 모델

**결정**: Node는 API 호출 이후의 서버 상태를 나타내고, Edge는 API 호출 자체를 나타낸다.

**이유**: `replay --to node.N`이 "Node N 상태로 만들어줘"라는 직관적 의미를 가짐. 같은 Node에서 다른 Edge를 타면 분기가 자연스럽게 표현됨.

---

## ADR-004: 매 호출 독립 CLI 프로세스 (REPL 대신)

**결정**: 매 명령이 독립 프로세스로 실행. 상태는 파일 시스템에 persist.

**이유**: Claude Code가 Bash tool로 한 명령씩 실행하는 구조. REPL은 interactive stdin이 필요하여 AI agent와 통합이 어려움. 파일 기반이면 프로세스가 죽어도 안전.

---

## ADR-005: 도달 불가능 호출은 감지만, 차단하지 않음

**결정**: 요청 값의 출처가 이전 응답에 없으면 `UNREACHABLE_SUSPECT` 경고를 남기되, 호출은 정상 진행.

**이유**: 시드 데이터를 직접 참조한 호출도 방어적 로직 테스트에 유용하다. 실제 클라이언트가 잘못 호출하는 케이스를 시뮬레이션하는 목적이 있으므로 차단하면 테스트 범위가 줄어듦.

---

## ADR-006: Replay 응답 불일치 시 중단 + diff

**결정**: Replay 중 원본 응답과 실제 응답이 다르면 즉시 중단하고 diff를 출력한다.

**대안 기각**: 경고만 남기고 계속하는 방식은 이후 호출이 깨진 상태에서 진행되어 디버깅이 어려워짐.

**후속 처리**: 중단 후 AI agent가 판단하거나 사용자 지침을 따름. 도구는 판정하지 않는다.

---

## ADR-007: 세션 이어가기 허용

**결정**: `--continue-from` 으로 이전 세션의 마지막 상태에서 새 세션을 시작할 수 있다.

**트레이드오프**: 이어가기 시 replay하려면 선행 세션까지 전부 재실행해야 함. 현실적 시나리오에서 허용 범위로 판단.

---

## ADR-008: JSON 기본 출력

**결정**: 모든 CLI 출력은 JSON. 사람용은 `--human` 플래그.

**이유**: 주 사용자가 AI agent. 비정형 텍스트는 파싱 오류를 유발한다. 에러도 structured JSON으로 출력.

---

## ADR-009: Node.js / TypeScript

**결정**: CLI를 Node.js + TypeScript로 구현.

**대안 검토**: Java/Kotlin(팀 스택 일치하나 CLI로 무거움), Python(의존성 관리 번거로움), Go(개발 속도 느림).

**선택 이유**: CLI로 가볍고, JSON 처리가 자연스럽고, npm 배포가 쉬움. 도구 복잡도 수준에서 팀 학습 비용 감당 가능.

---

## ADR-010: DB 리셋은 gradle 명령 위임

**결정**: CLI가 직접 DB를 조작하지 않고, config.yaml에 설정된 gradle 명령을 실행한다.

**이유**: Spring + Flyway 마이그레이션을 그대로 활용. 서버는 무상태 가정이므로 DB만 리셋하면 충분. 테스트컨테이너 기반이라 서버 종료 시 자동 정리됨.

---

## ADR-011: 템플릿 원본과 치환 값 이중 저장

**결정**: Edge 기록 시 `request.template`(원본)과 `request.path/body`(치환된 값) 모두 저장.

**이유**: Replay 시 템플릿 원본에 갱신된 바인딩을 적용해야 하므로 원본이 필요. 디버깅 시에는 실제 사용된 값이 필요. 둘 다 있어야 한다.
